## 怎么上传

**分步做法（含网页上传的点击路径）在 [`../UPLOAD.md`](../UPLOAD.md)。**

一个 mod 一个目录，**目录名就用 mod 的名字**：

```
incoming/
└── <mod 名字>/
    ├── SOURCE.md        ← 必需，照抄 SOURCE.template.md 填
    └── （原件的文件原样放进来：改动的文件、patch、zip 都行）
```

**最快的一步**：把 [`SOURCE.template.md`](SOURCE.template.md) 复制成
`incoming/<mod 名字>/SOURCE.md`，逐条填空。

`SOURCE.md` 必须写清这五件事（缺一件维护者就没法开工）：

1. **原件叫什么、从哪来** —— 仓库 URL / 发布页 / 群文件都行，要能追溯
2. **原作者是谁** —— 署名用；**未署名也要写明「原件未署名」**，不要留空、不要自己填一个
3. **原件的许可** —— 有没有 LICENSE、允许什么；没有就写「原件未声明许可」
4. **它改了什么** —— 尽量具体：改了哪些文件/哪些数据/哪些数值；只写「优化了平衡」这种没用
5. **它自带的素材是哪来的** —— 同人自制的？还是从游戏里解包的？（后者不会被收录，见下）

> **`SOURCE.md` 与 `PROVENANCE.md` 不是一回事。** `SOURCE.md` 是**投稿人**在 `incoming/` 里写的
> （原件是什么、从哪来）；`PROVENANCE.md` 是**兼容改写完成后**放进 `packs/<包 id>/` 里的
> **署名与来源档案**（六项，含「兼容改写者」与「改了什么」，见 [`../SKILL.md`](../SKILL.md) §10）。
> 一个在原件一侧，一个在成品一侧。

## 红线（上传前自己先看一遍）

- ❌ **不要上传任何游戏素材**（解包出的美术、音频、字体、数据导出物）。
  原件里夹着官方素材的话，**只传它的改动说明与代码/数据部分**，不要连素材一起打包上来
- ❌ **不要把已经能装的工坊包丢这里** —— 那种直接提到 `packs/`
- ❌ **不要**在 `incoming/` 里改引擎源码或试图让它「跑起来」；这里只存放原件
- ⚠️ 无法追溯来源、或原作者明确禁止再分发的 —— 不要上传

## 接下来会发生什么

1. 维护者读 `SOURCE.md`，判断这个 mod 里哪些部分**有接口**（能做进包）、哪些没有（写进说明）
2. 有接口的部分改写成工坊包格式，放进 `packs/`
3. 用引擎自己的装载器验一遍：

   ```bash
   node tools/check-packs.mjs --engine /path/to/Stronghold-Protocol-Forge --root packs
   ```

4. 通过之后，原件可以留在 `incoming/`（留档）或由维护者清掉
5. 完整规则见 [`../SKILL.md`](../SKILL.md)（尤其是 §14 素材红线、§15 做不成包的情形、§10 署名与许可）
